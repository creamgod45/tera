# Changelog

All notable changes to the Tera plugin. The first section is this branch (`codex/fix-tera-trimming-and-named-closers`,
pull request 1 into `dev`); commits are given by their short hash.

## 1.3.0

### Correctness

- No false errors for whitespace-trimming delimiters (`{%-`, `-%}`, `{{-`, `-}}`) or named end tags
  (`{% endmacro name %}`, `{% endblock name %}`) (`cbd7787`).
- HTML, CSS and JavaScript inside a template are parsed and highlighted by the native template data language support
  (`cbd7787`).
- Syntax errors for what the engines really reject, checked against Tera 1.20.1 and 2.4.0, including an unfinished filter
  chain such as `{{ x | }}` (`0831f6d`).
- Directories whose name ends in `.tera` or `.rs` are no longer read as files (`bd32133`).
- Documentation popups no longer fail on elements without a text range (`83a33e2`).
- Completion descriptions are separated from names by a gap (`1661e78`).

### Tera versions

- Tera 1.x or 2.x is detected per template (Cargo.toml, Settings); built-ins, deprecation markers, quick fixes and
  completion follow the version (`42c14c3`).
- *Migrate to Tera 2* for a file or the whole project (`42c14c3`).
- Tera 2 components: completion, checks, hover, navigation, typed parameters and the `{% <name> %}` body form
  (`42c14c3`).
- Type checks for Tera 2: unknown parameter types, defaults of another type, attribute values of the wrong type, filters
  and tests applied to a value of a kind they reject, with convert quick fixes (`576eb2e`).

### Macros and built-ins

- Macro and `import "..." as alias` analysis and completion: macro names, arguments, namespaces, keywords and template
  names (`cedfb70`).
- Go to definition (with a chooser for several sources) and hover documentation for macros, parameters and import
  aliases, including comment descriptions and `@param` types (`362c314`).
- Signatures, argument completion and hover documentation for Tera's built-in functions, filters and tests (`0ba19a8`).
- Functions, filters and tests registered from Rust (`register_function`, `register_filter`, `register_tester`) are known
  to completion, hover and navigation (`cd49b97`); what a custom filter returns is inferred from its Rust code, or from a
  `@returns` doc line (`2364fee`).

### Rust-aware template context

- Variables come from the Rust code that renders the template: struct fields, `context!` keys, loop and `set` variables
  (`da76b56`); structs generated by `macro_rules!` are read through macro expansion (`6460e5b`).
- Render sites are found by meaning, not by function name: a call that passes a template path string and a serializable
  value (`Serialize`, `Context`, `Value`) (`3571da1`). This covers any render function, generic page shells with
  `#[serde(flatten)]`, `let` locals, wrappers, and Rocket's form `Context` (errors, values, data fields).
- Layouts and partials inherit the variables of the pages that use them; component usages are followed through layouts
  and wrappers (`6a3f945`).
- Template roots come, in this order, from the *Template roots* setting, `Rocket.toml` (`template_dir`), `Tera::new`
  globs, `relative!`, `set_current_dir`, then `templates` (`1521e38`, `fbe0a64`).
- Variables for data that has no Rust type can be described in a JSON Schema file (`tera-context.json`, or a mapping in
  Settings); Rust wins on a conflict (`0831f6d`).

### Navigation

- Open a template from the Rust string that names it, honouring the template root and the working directory
  (`1521e38`).
- Complete template paths inside Rust strings; a `const` path counts as a render site (`1f26a91`).
- Blocks along the `extends` chain: go to the parent block, gutter icons for "overrides" and "overridden in N
  templates", `{{ super() }}` jumps to the parent (`5e4d836`).
- Gutter icon on a component definition lists its usages; on a call it lists the definitions. One icon per line when a
  line calls several components (`6a3f945`, `bf3d671`).
- Lists of usages and definitions show the line of the template and `file:line` beside it, in the gutter popups and in the
  Cmd+click chooser of current platform versions (`84c42b7`, `8764712`, `c07d543`, `0112101`).

### Refactoring

- Find Usages and Rename for blocks, macros, variables and components; dotted component names and closing tags are
  renamed together (`1b84fa7`).
- Renaming or moving a template file updates `extends`/`include`/`import` strings and the Rust strings that name it
  (`1b84fa7`).

### Editing

- Cmd+/ comments with `{# #}`, brace matching for `{{ }}`, `{% %}`, `{# #}`, auto-closing of delimiters (and backspace on
  an empty pair), folding of `block`, `for`, `if`, `macro`, `component`, `filter`, `raw`, `set` (`3111bed`).
- Live templates per Tera version (`macro`/`import` for Tera 1; `component`, `ternary`, `setblock`, `break`,
  `continue` for Tera 2). Statements are offered in template text only, never inside an open `{{ }}` or `{% %}`; the list
  comprehension is offered inside an expression only (`3111bed`, `2199c9f`).
- Reformat Code re-indents templates by tag nesting and changes nothing else (`6c33303`).

### Lists and maps

- `{{ list }}` and `{{ map }}` printed as they are get a warning that says what the engine prints (Tera 1 `[a, b]`,
  `[object]`; Tera 2 JSON), with quick fixes: loop, loop with `else`, `join` (`e79a7da`, `0831f6d`).
- The fixes also work after filters that keep or produce a list (`sort`, `values`, `keys`, `group_by`, ...) and after
  filters registered in Rust (`dd2de08`, `2364fee`). A switch in Settings turns the warning off.

### Errors

- Template errors in the Run window are links to the file, line and column, for Tera 1 and Tera 2 formats and Rocket's
  `template 'x': error:` line (`35d899b`, `c3af12f`).

### Examples and tests

- `examples/forms-tera2`: a runnable Rocket + Tera 2 app (`41306ad`).
- `examples/review-poc`: expense request, review and statistics app with a nested layout, a component library and
  Tailwind, with its own `cargo test`; `main.rs` is split into `controller/` modules (`ee2caad`, `0a1b658`).
- Plugin tests in three modes: `./gradlew test`, `-PwebTests=true`, `-PrustRoverHome=...`, plus `buildPlugin` and
  `verifyPlugin`. Error samples and print behaviour are real output of Tera 1.20.1 and 2.4.0.
- `MANUAL-CHECK.md` lists what only a person in the IDE can judge.

### Known gaps

- Zola awareness (variables of `page`, `section`, `config`), a block-level hover, Alt+F7 for dotted component names,
  bold highlighting of the matched name in usage lists, template paths produced by `macro_rules!`.
